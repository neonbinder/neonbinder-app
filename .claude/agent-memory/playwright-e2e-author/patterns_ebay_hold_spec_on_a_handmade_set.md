- **An over-80 stored title can only come from the generator.** `updateCard` refuses a TYPED title over 80, so the fixture is a hand-made card under a 60-character insert (`card-title-uses-short-name-for-titles` card C): every cut leaves it at 99 and it is kept whole. Compute the length with the bundled generator ([[title-fixture-arithmetic]]); a team on the card does not change it (teams are cut first). The fix path is typing a shorter title in the set builder drawer: fill, Enter, `Saved Card title`.
- **eBay needs no marketplace ids.** A hand-made set under real Baseball > 2024 > Topps lists on eBay; the collector cascade (`drillToCollectorChecklist` with `checklist: { type: "Insert", name }`) reaches it and the checklist/Sync label is `<year> <set> <insert>`. The hold order in the drain is photo, then required aspect, then title, so the card needs a photo and its facts (player, team, number) or it is held for the wrong reason.
- **A hold-only eBay run** reads `0 listed, 1 skipped` plus `1 held back:` and a list item that is a link named `#<number> <card> <sentence>`; its folded ledger is `Gathering data` (+ `Nothing new to send`) with no `List the cards` / `Set prices` / `Go live` step. Assert the absence of the sending steps next to the positive `gathered()`. Poll-first and press-first give the same end state for a hold.
- **A save that re-queues** shows the card under `Queued for the next sync` on Sync status with no Sync pressed (row text `<number> ... in <set label>`).
- **A seller spec needs three things in step**: the `@marketplace-seller` tag, an entry in `SELLER_SPECS` (project-scope.mjs) and a registry row. `shard-plan.mjs` throws "carries @marketplace-seller but is not in SELLER_SPECS" for a tagged spec that is not listed, so a new tagged spec breaks CI planning until project-scope is edited. A spec parked for a known sandbox blocker follows the NEO-453 precedent (untagged, `PROJECT_IGNORE` for both projects, a TEMPORARY comment) rather than going into the list red.
- eBay setup (ships-from, `Set me up` branch, policy picks) has no shared helper; the sibling eBay listing spec holds it inline. A second spec that needs a set-up connection copies a trimmed version, or the setup is promoted into `support/credentials.ts` (a harness change).
- **Split a seller flow at the blocker.** When one step of a flow needs a publish the sandbox refuses (NEO-453), put the shared flow in a local non-spec helper beside the specs (`tests/collection/ebay-over-80-title-fixture.ts`, `runOver80Flow(args, through)`): the active tagged spec stops before the publish, the parked untagged one runs it all. `shard-plan.mjs` scans spec text for the quoted seller tag, so the parked spec must not contain it, even in a comment. `playwright/expect-expect` warns on a spec that only calls the helper; end it with a real end-state assert (Profile, eBay not connected).
