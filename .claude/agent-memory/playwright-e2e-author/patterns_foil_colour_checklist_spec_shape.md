Learned writing `set-checklist-foil-colour-pro-set-metal` (2026-11-19):

- **Probe a real set's BSC names cheaply:** drill All Brands, pick the set, click its Insert type
  WITHOUT a stored checklist: the column lists every BSC insert ("<name> BSC" options). Each new
  read is a recorder miss on the first try (the column shows "Couldn't sync…" / "Sync failed");
  with the recorder running the next try answers. Then reseed: the probe wrote the column.
- **Reconcile Inserts' checklist matcher (`matchChecklistSections`, pass 3)** pairs a section
  whose name is a strict prefix of many BSC names with the one whose suffix is SHORTEST
  ("1989 Pro Set Base" -> "… Base Lazer Red", 63%), because a unique best ratio under 0.4 with
  the words contained counts. A sibling with an unguarded closer name (Mini) stays pending.
  Read `Ready (n)` rows in error-context before assuming what auto-matched.
- **City Designation cells on the Tidy Up walk (NEO-645, ported 2026-11-24):** the cell is the
  card's team cell as printed. Saved line "Saved 4 cards. Only your checklist was in play…" then
  "Teams from your checklist: 4 of 4 cards."; pill "4 need you, 3 to fix". "Miami" links the
  Marlins by itself (blue Career check only); "Cincinnati" is pink "Which team: Cincinnati" with
  list "We've got 3 teams from Cincinnati. Pick the one on this card." (buttons "Link to <club>
  · <era> · MLB", remember-box unticked for a place); "Los Angeles N" is pink "isn't linked to a
  team yet", "Printed on #89B-2, #89B-3", remember-box held then ticked: untick the enabled one,
  `fill` "Search all teams", pick the option. The answer reaches every card printing the name.
  Never `tidyForTheParallelBuild` here: it would link the first (1954 Redlegs) and CREATE a
  "Los Angeles N" team. Keep career gaps (`keepOpenCareerGaps`) before each `saveAndNext`.
- **A cross-card answer races Save & next:** the #89B-2 answer reaches #89B-3 a moment later;
  a save before it lands opens #89B-3 (cleared, kept on screen), after it goes to #89B-4. Gate the
  save on the live count (`expectCardsLeft(page, 1)`: both cleared cards left the count).
- The walk title drops a trailing "Base" from an insert name ("Tidy up 2026 Pro Set Metal 1989
  Pro Set") while main's `tidyUpTitle` trims by word; don't assert it until that settles.
- **Parallel build pairs a prefix-only number difference** (2026-11-24, `convex/lib/parallelCardLink.ts`):
  BSC Mini Prismatic Gold 89M-n pairs with Base 89B-n when the player matches, and the copy keeps
  the parallel's own number (89M-n). Assert by `editCardButton(page, "89M-1")` visible and
  `editCardButton(page, "89B-1")` count 0 under the Mini parallel (goBack, then the next option).
- **Card titles still opens** after the parallel-title fix: a copy whose title LEFT SOMETHING OUT
  (a team) counts too, not only over-80. Here: Gold 1, RWB 2, "Fix 3 card titles". Ledger clause
  "1 title needs a fix"; dialog sections are regions "<parallel> 1 title"; fields are named
  "Title for <parallel> #<number> <player>" (the parallel IS in the name). Offline tsx titles
  can disagree with the app on what is left out: read the dialog from a run.
- Ledger lines: BSC-linked ones are buttons ("X — Built 4 cards, 185 on BSC that … doesn't
  have"), checklist-only ones plain list items; `getByText(/^X — Built 4 cards/)` finds both.
- **Collector drill:** under an insert the next listbox is "<insert> parallels"; a row with a
  run is named "<name> , numbered to 5" (space before the comma possible: regex `^X ?, …$`),
  "one of one" for 1/1; the visible "/5" is aria-hidden but `getByText` still finds it.
- A card's own run: `editCardButton` -> dialog spinbutton "Print run" value, "Close card detail".
- A probe copy of a spec (operator fix inserted, upload made conditional) generated by a
  script from the spec keeps the two in step; delete it before the commit.
